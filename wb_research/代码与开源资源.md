核查日期：2026-10-21。下列开源代码已在线核对 README、部分目录或源码入口；未在本机安装或完整运行这些外部项目。许可证说明来自核查到的仓库，不代替对具体模型、数据及依赖许可的检查。

## 1. 值得先读的一手方法资料

| 资料 | 最值得提取的部分 | 本次阅读边界 |
|---|---|---|
| [Taylor 等，2013，A defined methodology for reliable quantification of Western blot data](https://pubmed.ncbi.nlm.nih.gov/23709336/)；DOI 10.1007/s12033-013-9672-6 | 抗体/样本稀释与响应范围验证 | PubMed摘要及图注，不冒充全文细读 |
| [Taylor & Posch，2014，The design of a quantitative western blot experiment](https://pubmed.ncbi.nlm.nih.gov/24738055/)；DOI 10.1155/2014/361590 | 从样本到定量的实验设计 | 文章索引与摘要 |
| [Janes，2015，An analysis of critical factors for quantitative immunoblotting](https://pubmed.ncbi.nlm.nih.gov/25852189/)；DOI 10.1126/scisignal.2005966 | 为什么像素数字可能只是“伪定量” | PubMed摘要及可见图注 |
| [Degasperi 等，2014，Evaluating Strategies to Normalise Biological Replicates of Western Blot Data](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0087293) | 参考选择、误差及归一化后的统计相关性 | 全文相关分析段落 |
| [Taylor 等，2022，A critical path…](https://www.nature.com/articles/s41598-022-22294-x.pdf)；DOI 10.1038/s41598-022-22294-x | Fig. 3流程、Fig. 4同膜/跨膜计算、补充Excel模板 | PDF正文和数据分析方法 |

优先顺序建议：先理解 2022 年的分析层级，再看 ImageJ 的操作与代码定义；针对统计问题读 Degasperi，针对自动识别读 GelGenie。厂商技术文档适合明确设备操作，跨平台能力仍需独立验证。

## 2. 开源项目怎么选

| 项目 | 适合借鉴 | 已核查的许可/局限 |

| [blotRig](https://github.com/ucsf-ferguson-lab/blotRig) | 平衡实验设计、技术重复与实验管理 | DESCRIPTION 标记MIT；完整运行未实测 |
| [BandQuant](https://github.com/wanhj-git/BandQuant) | 接近WB产品的整体交互与计算边界 | MIT；README说明依赖配套后端；部分检测服务源码也在库中，完整部署尚未核验 |

**研发判断**：要从算法开始，先读 GelGenie；要从可信定量开始，先读 BlotTool 与 ImageJ；要研究完整产品体验，再看 BandQuant。不要因某项目支持“自动识别”就假定它已经解决线性范围和生物学重复问题。

### 2.1 ImageJ：直接阅读核心源码

[GelAnalyzer.java 官方源码](https://imagej.net/ij/developer/source/ij/plugin/GelAnalyzer.java.html)

建议关注泳道选择、曲线生成、反相选项和峰标注。屏幕峰面积的单位/缩放与原像素积分的定义不宜混用。它适合建立“已有手工流程到底算了什么”的明确基准。

### 2.2 GelGenie：自动分割优先参考

[论文](https://www.nature.com/articles/s41467-025-59189-0) · [Python说明](https://github.com/mattaq31/GelGenie/blob/main/python-gelgenie/README.md) · [标注数据 DOI](https://doi.org/10.5281/zenodo.14641949) · [论文代码归档 DOI](https://doi.org/10.5281/zenodo.15054646)

论文报告使用500多张人工标注gel图训练分割模型。对本项目的价值主要是训练/推理组织与mask定量思路；不把这些图统一称为WB数据，也不宣称模型已在用户实验室验证。

已核查的代码路径：

- [segmentation/evaluation/core_functions.py](https://github.com/mattaq31/GelGenie/blob/main/python-gelgenie/gelgenie/segmentation/evaluation/core_functions.py)：包括 `model_predict_and_process`、多增强推理及结果导出相关函数。
- [segmentation/evaluation/__init__.py](https://github.com/mattaq31/GelGenie/blob/main/python-gelgenie/gelgenie/segmentation/evaluation/__init__.py)：模型加载及CLI管线，包括 `model_eval_load`、`segmentation_pipeline`。
- [classical_tools](https://github.com/mattaq31/GelGenie/tree/main/python-gelgenie/gelgenie/classical_tools)：传统分割基线。

下面是按当前源码参数整理的使用形式，**不是已在本机运行成功的命令**：

```bash
git clone https://github.com/mattaq31/GelGenie.git
cd GelGenie/python-gelgenie
# 先在独立环境按项目文档安装适合硬件的PyTorch与requirements
python -m pip install -e .
quick_seg --help
```

根据已核对的CLI，推理接受模型父目录、实验名和checkpoint epoch：

```bash
quick_seg --model_folder /ABSOLUTE/MODEL_PARENT \
  --model_and_epoch ACTUAL_EXPERIMENT_NAME ACTUAL_EPOCH \
  --input_folder /ABSOLUTE/INPUT \
  --output_folder /ABSOLUTE/OUTPUT
```

上面大写项均需换成实际存在的路径/模型。模型加载还需要 `config.toml` 和相应 checkpoint；不能只下载任意一个权重文件就假定该接口能读。参数 `--run_quant_analysis` 在当前源码中进入有真值mask的评估路径，不能不看文档就把它理解为临床/实验完整定量。

## 3. 本次提供的可运行参考代码

本地 `code/wb_reference.py` 使用 Python + NumPy + Pillow 独立实现，没有复制外部项目的代码。目的是把方法转成可以检查的数值流程。

### 已实现

- 单平面灰度读图，保留16位像素值；明确拒绝隐式RGB转换与多页选择。
- 显式亮/暗极性和编码上界，避免默认按255反相。
- 原始矩形ROI积分、局部背景并集均值、面积缩放扣除。
- 保留负净信号，报告数字端点clipping、背景离散程度。
- 用户指定目标区间内的经典候选检测；候选框与正式测量分离。
- 按显式ID匹配目标与参考，检查样本、泳道、生物学单位与膜。
- 拒绝未复核/已标记饱和/净信号非正的默认归一化。
- 同膜技术重复合并与对照描述性fold change。
- 原始数据CSV、归一化CSV、生物学汇总CSV、参数与hash审计JSON。

### 使用方式

```bash
cd wb_research/code
# 缺依赖时在自己的独立Python环境安装；本次运行用的是已有依赖
python3 -m pip install -r requirements.txt

# 数值/文件行为检查
python3 -m unittest discover -v

# 生成一个新的纯合成示例目录
python3 make_demo.py ../my_demo

# 运行定量；输出目录必须尚不存在
python3 wb_reference.py ../my_demo/config.json ../my_demo/results
```

仓库中已附 `demo/` 及其计算结果，不必重新生成。文件名均明确标记SYNTHETIC，不是真实实验图。

### Python函数示例

```python
import numpy as np
from wb_reference import measure, propose_rectangles

image = np.full((80, 120), 1000, dtype=np.uint16)
image[30:40, 20:40] = 1200

result = measure(
    image,
    roi=[20, 30, 40, 40],
    backgrounds=[[20, 15, 40, 25]],
    polarity="bright",
    ceiling=4095,
)
print(result["corrected_sum"])  # 40000.0

boxes = propose_rectangles(image, window=[0, 25, 120, 45], ceiling=4095)
print(boxes)  # 仅为待复核候选，不会自动赋予样本身份
```

坐标采用原图0起点的 `[x0,y0,x1,y1]`，右下边界不包含在ROI中；这是软件坐标约定，需要在界面中转换一致。

### 配置文件的关键字段

参考 `demo/config.json`：

```json
{
  "images": {
    "image_1": {
      "path": "raw_target.tif",
      "polarity": "bright",
      "ceiling": 65535
    }
  },
  "control_group": "control",
  "records": [
    {
      "id": "target_lane_1",
      "role": "target",
      "image_id": "image_1",
      "sample_id": "sample_1",
      "bio_id": "animal_1",
      "lane_id": "original_lane_1",
      "blot_id": "membrane_1",
      "group": "control",
      "analyte": "AKT",
      "ref_id": "loading_lane_1",
      "roi": [20, 30, 40, 40],
      "backgrounds": [[20, 15, 40, 25]],
      "reviewed": false,
      "linear_range_validated": false
    }
  ]
}
```

该片段用于解释字段；要完整运行，还必须增加ID为 `loading_lane_1`、role为 `reference` 的对应记录、实际图片及坐标。编码上界只是示例，不能不核查就沿用65535。

`reviewed` 表示操作者已确认条带、背景与对应关系；不能直接把所有真实数据批量设为true。`linear_range_validated` 是实验记录声明，程序不会因此替你完成实验验证。

### 尚未实现的部分

专有仪器格式、完整通道/多页支持、marker自动识别、弯曲泳道跟踪、任意多条带身份推断、学习式模型、IBC校准、配对/混合模型、显著性检验、正式GUI与出版排版。

当前候选检测对重叠条带、强拖尾、邻近背景中有其他蛋白、极弱条带或不规则膜可能失败。当前方法也没有LOQ/LOD实验判定；正净信号并不自动代表已达到可定量下限。

### 示例应看到什么

合成图中：6个独立生物学单位，每单位2条技术泳道；对照3个、处理3个；每泳道1个目标和1个参考，共24条测量记录。参考条带仅用于演示，不构成GAPDH适用于真实实验的建议。

人为在最后一条目标ROI放了一个到达4095的像素，应有1条目标被阻止归一化。其余技术测量按单位合并，处理组的描述性平均fold change应约为2。

这些结果证明示例的计算路径可运行，不是对真实WB数据的性能保证。
