## Final review repair wave (base `3848520`)

1. **Credential ownership:** `OsStore` acquires a lifetime OS file lock before `Auth` or scientific initialization. One v2 hash of actual Tauri application identifier, exact issuer/client and canonical app-data root names the OS credential, nonsecret restore marker and nonsecret lock. Independent construction in another process or the same process is refused while the owner or a pending storage closure retains its store. The lock file is never unlinked; the OS releases ownership on normal exit/crash. A proven duplicate owner uses a nonblocking explanatory dialog and initializes no engine/account state. After the scoped startup correction, lock I/O errors instead yield an inert unavailable account and preserve the guest scientific session/worker; no account operation bypasses the guard. Unconfigured/invalid configuration uses an inert account without touching account storage. Different app IDs and roots sharing the issuer do not share credentials. Old v1 credentials are neither accessed nor deleted, so upgrades require a fresh login. Guest use and explicit memory-only login in the owning app retain their existing behavior.
2. **Device-list state:** the hook fetches the sanitized native snapshot after both list success and failure. Identity, request and generation checks surround both awaits. Offline/recovery/storage/terminal outcomes reach the sidebar/panel; old responses cannot revive a logged-out or switched account. Session arrays and snapshots retain their existing credential-free/URL-free contracts.
3. **Native device metadata:** Rust sends compile-target platform and a fixed human-readable label (`Titan on macOS`, `Titan on Windows`, `Titan on Linux`; other targets default to `desktop` / `Titan Desktop`). The service validates platform and bounded non-sensitive display text before authorization, binds it to the code in `GrantContext`, copies it into the minted session, and retains it during refresh. No installation/hardware identifier, hostname, OS username, OS version or science data is collected. Older clients retain defaults; metadata never grants authorization. Additive migration `0004_grant_device_metadata` was tested on disposable PostgreSQL test databases only. Controller live service/database were not migrated or restarted; they must be updated before new live acceptance.
4. **Password wording:** actual browser tests entered only a synthetic localhost account password. No OS/Keychain or real user password was entered.
