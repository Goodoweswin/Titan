# Titan 账户登录与现有 ECS 共存设计

日期：2026-11-12（北京时间）。状态：用户已确认执行；本地实现中，没有部署账户服务。

独立 builder check 已完成，未发现阻碍制定实施计划的重要缺口。确认后，本设计作为后续实施依据；旧计划中的“ECS 未提供”、空白服务器部署假设与旧源码基线说明由本设计更新。

## 1. 目的与依据

为 Titan 0.4.1 接入真实账户登录，使用户可以注册、验证邮箱、恢复密码、编辑昵称及管理登录会话。游客仍可完成本地科研工作。账户服务独立于科学计算，不接收实验图像、路径、测量数据、项目名称或研究足迹。

范围沿用仓库 `docs/superpowers/plans/2026-11-12-ecs-account-system.md` 记录的既有产品决定。用户本次提供的《ECS 跨产品账号登录开发交接》补充了服务器约束：杭州 ECS 为 2 vCPU / 2 GiB，已经运行科研 taobao，账号服务、数据库及网关均不是空白环境。交接记录的现场核验时间为 2026-11-12 14:33:09 UTC+08:00；本轮没有重新连接服务器，不将当时的空闲资源当作当前容量保证。

本设计的工程选型是实施建议，不将其标记为用户已确认。

## 2. 首版交付范围

- 邮箱密码自助注册、邮箱验证与重发、登录、密码找回与重置。
- 注册未验证时可进入验证提示页，但不能获得桌面账户 API 凭据。
- 显示服务端确认的昵称、邮箱、验证状态、创建日期；仅昵称可修改。
- 当前会话和其他设备会话列表，退出当前会话、撤销指定会话、撤销全部会话。
- 管理员通过受限后台禁用账户；禁用、密码修改和重置使现有凭据失效。
- 错误密码、取消登录、服务故障、断网、令牌过期、凭据库拒绝访问均有明确反馈。
- 当前本地研究足迹保持设备范围，不在切换账户时被误认为云端账户数据。

不包含付费权益、防破解或商业许可证、AI 服务、云同步、团队、第三方账号绑定、邮箱变更。登录本身不能作为本地功能不可破解的保证。

## 3. 集成基线

当前主工作区是 0.3.4 基线，包含尚未提交的账户 UI 和其他改动，不能直接据此重建覆盖 0.4.1。实际安装包对应 `release/account-update-0.4.1` 源码副本，其上游为 `codex/sidebar-system-appearance` 的 `2309e8b`。

实施时创建独立的 `codex/titan-account-login` 工作树，以 `2309e8b` 为基础，先比较并导入该源码副本的产品源码、测试、锁文件和配置，生成可追踪的 0.4.1 集成基线提交。排除构建缓存、虚拟环境、node_modules、发布包及私密配置；不得整目录复制覆盖或把其他未提交改动一并带入。核对 WB、IF、统计绘图、项目管理、配色和账户页均保留后，再接入认证。

新账户服务在 `services/accounts/`，部署材料在 `deploy/accounts/`，桌面桥接在 `src/account-bridge.ts` 与 `src-tauri/src/auth/`。服务依赖独立锁定，不进入 Python 科学引擎。

## 4. 用户可见流程

点击账户页“登录 / 注册”，Titan 启动系统浏览器，展示 Titan 自己的登录网站。网站提供登录、注册和找回密码；注册后提示检查邮箱。验证成功后继续原有授权流程；若流程已经过期，则提示回到 Titan 重新登录。

网页登录完成后，浏览器显示“登录完成，可返回 Titan”，桌面账户页显示真实资料与会话管理。浏览器关闭不等于取消桌面事务，桌面提供取消按钮，并在超时后恢复可重试状态。重复点击复用当前事务或明确提示已在进行。

用户最新纠正：“账户页面是中栏，不是独立弹出页面”。账户页位于应用壳的中栏，保留可用的左侧导航与全局浏览标题/后退前进；账户项显示选中状态，无右侧检查栏。打开账户只暂时隐藏并隔离科学工作区，返回原页面不重建编辑器或丢弃 WB/IF/统计草稿；从账户跳往另一分析或模块仍使用既有离开保护。Escape 不关闭账户中栏，退出所有设备的确认仍可用 Escape 取消。账户页保留既有布局与研究足迹，添加必要的昵称编辑、会话列表、退出与状态反馈。断网时显示“离线，账户状态待确认”；本地工作区仍可使用。切换账户清除上一账户的资料与请求状态，迟到响应不得恢复旧账户。

本地退出与浏览器登录会话分别处理。离线退出立即清除本机凭据，并说明服务器会话尚未确认撤销；切换账号使用显式重新认证，不静默回到上一个浏览器账户。

## 5. 认证架构与边界

沿用既有方案的 Django + Django REST Framework + Django OAuth Toolkit、PostgreSQL。不引入 Redis 或独立身份平台。科研 taobao 的 Fastify 实现作为行为参考，不调用其认证接口或复用用户表、Cookie、凭据。

采用 OIDC 授权码流、PKCE S256 和 RS256。桌面是 public client，没有固定 client secret；只启用已登记客户端所需的授权方式，不开放动态客户端注册、implicit 或 password grant。OIDC 组件文档已确认支持授权码流；实际版本、扩展点和行为在 P0 中验证并锁定。

Rust 生成 state、nonce 和 verifier；临时监听只绑定 `127.0.0.1`，路径固定 `/oauth/callback`。授权服务器仅允许登记的回环 host/path，端口变化按原生客户端规则处理，拒绝任意重定向。回调只接收一次性 code/state 或错误，限制请求大小、时长、请求方法与参数重复；错误 state 不应消耗合法事务。

Rust 完成换码、签名及 issuer/audience/nonce/时间校验。生产 issuer 和允许的 URL 来自受控配置，React 不能指定接收凭据的地址；生产网络请求禁止明文与跨来源重定向。HTTP 仅用于开发回环服务和标准允许的本机回调。

access token 初始有效期 10 分钟，refresh family 绝对期限 30 天。账户 API 查询服务端用户及会话状态。刷新须轮换、原子提交并检测重放；同时刷新串行化，无法确定刷新是否成功时要求重新登录，避免重试旧 refresh token。改密、重置、禁用及撤销须立即作用于已有 access token。

长期凭据保存于 macOS Keychain / Windows 凭据库；access token 优先仅驻留 Rust 内存。凭据库失败可以明确选择仅本次运行登录，不能自动明文保存。React、日志、localStorage、项目文件均不接收原始凭据。

## 6. 数据和接口合同

User 使用稳定 UUID、唯一规范化邮箱、昵称、创建时间、验证时间与禁用状态。邮箱策略为去除首尾空白并采用一致的大小写不敏感唯一规则，不删除点号或 `+tag`。密码使用框架自适应哈希，参数经实际运行环境测量；限流同时覆盖来源与账户标识，使用共享数据库状态，不依赖单进程内存。

DeviceSession 记录所属用户、创建/最近活动/绝对到期时间、撤销状态、平台与用户可读名称，并关联 token family。安装标识只用于展示，不代表硬件身份。验证和重置链接单次使用、限时有效；重发不得复活已消费的链接。审计记录不保存密码、令牌或完整回调 URL。

网页注册、登录、验证和恢复使用服务端会话，独立 host-only Cookie，正式环境 Secure / HttpOnly / SameSite=Lax，并校验 CSRF 与允许的来源。代理头仅信任已验证的网关路径。

| 接口 | 合同 |
| --- | --- |
| OIDC discovery / authorize / token / JWKS / userinfo / revoke | 组件提供，限制客户端、scope 和授权方式 |
| `GET /api/v1/me` | 当前用户最小资料与当前会话 ID |
| `PATCH /api/v1/me` | 只允许修改昵称 |
| `GET /api/v1/sessions` | 只返回当前用户脱敏会话 |
| `DELETE /api/v1/sessions/{id}` | 校验所有权，幂等撤销 |
| `POST /api/v1/sessions/revoke-all` | 要求近期重新认证，服务端验证认证时间 |
| `/health/live`、`/health/ready` | 存活与依赖就绪，不泄露配置 |

错误包含稳定 code、可读 message 和 request_id；区分 401、403、429 与服务不可用。注册和找回的公开响应避免泄露账户是否存在。邮件通过事务 outbox 记录发送意图，应用内独立管理命令处理重试，控制并发与频率；本地测试邮件留在测试环境，正式投递适配器在明确服务商后接入。

P0 必须核实组件的 token 存储格式、轮换和重放行为。若组件保留可恢复令牌，实施文档明确其风险、数据库最小权限和加密备份；不得声称令牌已摘要保存。不能仅凭启用框架就宣布这些语义完成。

## 7. ECS 共存方案

建议名称为 `titan-accounts`，目录 `/opt/titan-accounts/releases/<id>/` 与 `/etc/titan-accounts/`，独立 Compose project、卷、数据库及运行角色。它们当前均未创建。

初始方案使用独立 PostgreSQL 容器，避免对旧生产数据库执行账号创建和迁移。先在本地限制账户应用及数据库的资源，测量空闲、并发登录、发信重试、重启峰值；新增常驻服务的初始试验内存上限总预算为 384 MiB，不是已验证容量。具体拆分、数据库连接数、哈希参数、CPU/PID 上限由实测决定。若预算下不能稳定运行，暂停共机上线，给出扩容或独立实例的具体方案，不通过占用旧服务预算维持运行。

80/443 继续由现有 Caddy 提供。Titan 使用独立域名，网关仅新增该域名路由并接入 Titan 对外网络；Titan 数据库仅在其内部网络可达。不能让新服务覆盖旧网络中的 `api` 别名，不能改动旧网关固定地址和旧 API 的受信代理规则。

现有网关 `admin off`。部署材料须基于届时读取的完整当前配置生成增量版本，先验证配置，再安排可回退切换；不假定可直接 `caddy reload`。只读预检确认端口及网段后，才选私测回环端口；不预占 18443，不公开数据库或调试端口。

服务端仅运行固定构建产物，配置资源上限、日志轮转、健康检查及重启策略。私密文件独立注入，不写进仓库或输出完整 compose 展开配置。保留旧容器、卷、证书、停止的演练容器、业务数据和通知开关。

部署前对新服务建立独立加密备份、恢复到隔离环境并验证。恢复后通过新的会话失效 epoch 强制重新认证，防止数据库回退恢复已撤销会话。回退只切换 Titan 产物及新增网关配置，保留卷；数据库迁移采用向后兼容步骤，回滚不覆盖已产生的业务数据。
