# Titan WB 泳道优先分析更新设计

日期：2026-10-31。状态：根据本次聊天已认可的方向整理；下列技术默认值为实现建议，不代表已完成。

## 用户认可的方向

先建立每个样本的泳道，再在泳道内提取灰度曲线、确定峰范围、扣背景积分。优先测量内参，逐个添加目标蛋白，目标数据按稳定泳道身份关联对应内参并归一化。保留自动建议、手动对齐和人工确认。

用户报告的关联问题也纳入这轮更新：导入缓慢、灰度调色板页被拒绝、16 位预览与原软件黑白方向相反。

用户补充要求：UI 与算法同步更新，系统尽量简单。默认流程减少入口、重复表单和重复确认；不把后台数据结构或算法参数直接暴露为日常操作。

## 当前证据

- `detection.py` 当前按指定区域的横向信号阈值产生矩形候选，没有独立的泳道几何模型。
- `appendCandidates` 按候选下标复用泳道，漏检中间一条时存在样本错配风险。
- 截图中的长横框跨越多个样本，当前会作为一个 ROI 积分，不能用于逐样本定量。
- `108603.tif` 共两页：第 1 页为 LZW 压缩的 uint8 灰度反向调色板图；第 2 页为 2688 × 2200 的 uint16 灰度图。调色板三通道相同；显示方向与第 2 页数值方向相反。
- 本机单次性能记录见 `artifacts/import-performance.json`：直接解码第 2 页约 0.002 s，生成预览约 0.072 s，安装版仅执行 health 的完整进程调用约 15.6 / 23.3 s，安装版导入约 19.5 s。这是单机样本，不是普遍性能保证。
- 当前安装版每个命令启动一个 PyInstaller onefile 引擎；多页检查、预览和导入分别调用引擎。

## 操作流程

导入原图 → 选择膜/分析区域、排除 marker → 自动建议泳道 → 调整数量与边界、绑定样本 → 确认泳道 → 测量内参 → 添加目标并对齐泳道模板 → 确认目标峰和背景 → 自动计算归一化 → 复核、保存、导出。

- 泳道是纵向的图像分区，切分采用原图坐标，不破坏性拆图。
- 泳道身份和图像内的位置分开保存；位置调整、漏检或图像顺序改变不得更换样本身份。
- 同一原始泳道的目标与内参共用 lane_id。不同膜分别建布局，禁止依据图片顺序或相近位置自动跨膜绑定。
- 首个确认的内参布局可作为同膜后续图像的模板；用户可调整模板平移、横向间距及单泳道宽度。坐标最终落实到各图的原始整数像素。
- 本轮以直泳道为主；不实现弯曲泳道自动展开、大角度校正或原图重采样。复杂图像可回到人工边界/ROI 编辑。
- 自动识别给出候选与疑点，不自动证明蛋白身份。用户指定蛋白名和目标区域；多峰、弱峰及数量冲突要求确认。

## 测量合同

- 识别阈值只用于提出位置；正式测量包含确认峰区内的全部原始像素，不只统计超过阈值的像素。
- 泳道曲线使用每个 y 位置的横向像素总和。显示可以降采样，检测与积分使用完整分辨率。
- 首轮沿用现有背景合同：确认的局部背景 ROI 并集均值；净积分 = ROI 像素总和 − ROI 面积 × 背景均值。自动推荐背景区域，人工可调整。
- 不在本轮悄悄替换为 rolling-ball、任意曲线基线或阈值面积；今后如增加其他方法，应独立命名并记录参数。
- 峰区积分必须与现有 `measure` 对相同原图/ROI/背景的结果一致。曲线使用总和，避免变宽泳道因“均值曲线面积”而丢失宽度因子。
- 未检出保持该泳道的空位，结果为空并附原因；未检出不自动等同数值 0，不重新排列后续泳道。
- 内参净信号非正、未确认、饱和或缺失时，不输出有效归一化值。沿用现有线性范围、编码范围与复核标记。
- 内参、目标、背景或样本映射变化后，相关结果失效并触发就绪输入的重新计算；迟到的旧结果不能覆盖当前版本。

## 图像显示与原始数据

- 支持 8/16 位单通道灰度 TIFF，包括 MINISBLACK、MINISWHITE 和灰度调色板；彩色调色板不自动转换后参与定量。
- 灰度调色板保留原始索引值及 LUT 元数据；测量不使用 RGB 转换后的显示图。文件的采集/处理来源仍需用户确认。
- 第 1 页的 LZW 读取可使用 Pillow 的原始 P 模式，不经过 RGB 或 L 模式转换；所有支持路径验证形状、位深与数值保持。
- 新增“显示反色”，默认考虑文件 LUT/photometric，用户可切换；该设置不改变原始像素、分析极性、ROI、有效结果和复核状态。
- “原始信号方向”负责计算极性，与“显示反色”分开。不能根据屏幕是黑条带就自动选择 dark。
- 保留多页选择、页码、原文件 SHA256，以及单文件 50 MiB / 每页 2500 万像素限制。

## 数据结构建议

采用 schema_version=2，继续复用现有 images、lanes、samples、rois、settings，增加：

```text
LaneLayout {
 id, image_id, membrane_id, window: Rect,
 columns: [{ lane_id, rect: Rect }], excluded_regions: Rect[],
 source_layout_id: string | null, confirmed_revision: number | null
}
BandSet {
 id, layout_id, analyte, role: target | reference, window: Rect,
 reference_set_id: string | null,
 assignments: [{ lane_id, roi_id: string | null,
                 status: pending | accepted | not_detected | excluded }]
}
ImageAsset 新增 display_inverted: boolean（只影响显示）及可选 LUT/photometric 来源元数据。
ROI 新增可选 lane_layout_id、band_set_id；原 rect、backgrounds、reference_id 测量合同保持。
Project 新增 lane_layouts: LaneLayout[]、band_sets: BandSet[]。
```

同一泳道可绑定多个目标和一个明确选定的参考集合；多个参考集合时要求显式选择，不按名称或位置猜测。技术重复仍可多泳道共用 sample_id。

旧项目读入后在内存迁移至 v2，保留已有 ROI 和引用；没有可靠来源的泳道边界不凭空重建。首次保存迁移项目时写入新副本，原 v1 项目保持。旧结果不得作为新算法的已复核结果自动保留。

## 引擎与性能

- 每个 App 进程持有一个常驻本地 worker，稳定使用当前 session 的 PID/token；不同 App 实例不共享 worker。
- 新增 `--stdio-server` 流式 JSON 协议，带 request_id；保留原来一次性 JSON 调用，兼容测试脚本和 CLI。
- 用受控串行队列协调请求，超时或 worker 退出后恢复到可重启状态；请求 ID 必须匹配，禁止旧响应串到新请求。
- PyInstaller 改用 onedir 资源目录，避免每次调用单文件引擎；macOS 与 Windows 都通过应用资源目录定位入口及依赖。
- 缓存已解码图、预览和曲线；原始像素缓存上限 256 MiB，预览/曲线合计上限 32 MiB，LRU 淘汰。缓存键包含内容 hash、页码及相关分析输入。
- 定量仍校验原文件 SHA256；内容改变不能被缓存掩盖。显示设置不进入数值缓存键。
- 性能目标（待测）：本机 App 冷启动至引擎就绪 ≤3 s；引擎就绪后该约 12 MB TIFF 的页面列表 ≤1 s、预览 ≤1 s、确认单页导入 ≤2 s。使用安装包、同机 5 次测量并报告中位数和最大值；不以目标代替实测。

## 界面与交付

- 主流程收敛为“内参 / 目标 / 结果”三个步骤；泳道设置并入内参步骤，不再单独占一个导航入口。既有手动 ROI 路径保留在“手动调整”，用于旧项目和复杂图像。
- UI 与相关算法一起交付、一起验收；不先堆算法按钮，再另做一套复杂界面。复用当前浅色工作台的视觉风格，优先改善信息层级与画布空间。
- 泳道边界、峰区和背景使用不同覆盖层；不再把“选择整排分析区域”直接写成一个正式条带 ROI。
- 目标与内参的图像位置、泳道编号和样本名称在确认界面可见；内部 UUID、hash 等仅放在详情。最终表格按膜、泳道/样本、蛋白显示净积分与对应比值。
- 原图、页码、布局、峰区、背景、方法、映射、软件版本和结果版本一并保存、导出；显示反色的状态与定量方向分别记录。
- 保留现有 macOS 14+ Apple Silicon / Windows x64 支持范围；跨平台声明依赖实际构建与验收。
- 用户 TIFF 用于本机兼容性/交互检查，不加入公共测试数据。不预设它的样本数、内参身份或实验分组。

### 简化 UI 的具体约束

```text
实验名称                         保存状态   保存   导出
                 内参   →   目标   →   结果
蛋白列表          原图与覆盖层                 当前操作
内参              泳道 / 条带 / 背景           当前步骤需要的字段
目标 A                                       一个主要动作
目标 B            选中泳道后可展开曲线          手动调整 / 高级设置
```

- 默认以原图为主；已有侧栏用于简短的内参/目标列表，不再同时堆叠图像树、泳道树和多组功能导航。来源文件、页码与详细元数据按需查看。
- 内参页：导入内参图、拖选分析区域，自动建议泳道和峰区；正常结果按集合确认一次，弱峰、多峰、边界冲突留在当前画面处理。不同输入变化后只重确认受影响部分。
- 目标页：填写目标名、选择图像或同图区域，复用泳道与样本；有偏移才显示对齐操作。添加下一个目标沿用已确认的关系，不重新填写样本表。
- 结果页：默认显示每泳道/样本的内参、目标及归一化值；原始积分、背景、审计和统计设置按需展开。分组/重复关系必须明确设置后才展示生物学 n 与组间检验；只做泳道归一化不强制填写整套统计表单。
- 当前任务面板默认最多 4 个可编辑字段、同时只显示 1 个主要动作；动作随状态从“识别泳道”切换为“确认内参”或“确认目标”。保存、撤销、显示反色和缩放放在固定位置，避免随任务漂移。
- 优先用拖选区域、拖动边界和点击泳道；y 起止坐标、阈值、平滑、最小宽度、内部 ID、IBC 等收进高级设置，不作为正常流程的必填项。
- 灰度曲线只在选中泳道或主动展开时出现，并与原图峰区联动；不常驻展示全体泳道曲线或多排指标卡片。
- 主流程文案使用“泳道、内参、目标、背景、结果”；schema、worker、LUT、request_id 等实现术语不出现在普通操作中。分析方向或编码上界缺失导致无法测量时，在当前步骤明确说明如何补充，不用折叠设置掩盖阻塞。
- 自动建议和确认集中在原图一处完成，避免连续弹窗；缺失/可疑泳道直接标色并可点击定位。保留必要的科学复核，不要求重复确认同一份未变化的数据。
- UI 验收增加“第一次使用能沿三步走通、无需输入像素坐标、添加第二个目标不重复配置样本、正常流程不打开高级设置”。在 1080 px 与大字号下检查可读性和主要操作可达性。

## 验收边界与参考

Fiji/ImageJ 经典流程是泳道 ROI → 曲线 → 手动确定基线/峰 → 测峰面积，并非全自动蛋白识别：
https://imagej.net/ij/docs/menus/analyze.html#gels

独立数值对照使用相同原始像素、ROI 与背景的 ImageJ RawIntDen/Area/Mean 计算，不直接把缩放后的 Gel Analyzer 绘图面积当成同单位的原始积分。

合成已知数值图验证算法与测量；本机用户图验证兼容性和操作；独立 Fiji 对照验证给定 ROI/背景的测量口径。三者均不自动证明真实 WB 的抗体特异性、实验线性或生物学结论。
